## 이번 검증 중 수정한 문제

1. 메뉴·근무표 Mock 저장소의 Web Locks 래퍼 타입 추론 때문에 타입 검사가 실패하던 2곳을 명시적 비동기 반환으로 수정했습니다.
2. ExcelJS 동적 import의 잘못된 기본 내보내기 타입 처리를 수정했습니다. 실제 다운로드까지 확인했습니다.
3. 대시보드 ‘관리 중인 식재료’가 등록 수 대신 구매 이력이 있는 품목 수를 표시하던 집계를 등록 목록 기준으로 수정했습니다. 구매 이력 없는 식재료를 포함해 7개로 표시됩니다.
4. 필수 형식 선택 규칙에 맞춰 기존 중복 업로드 테스트를 갱신하고 AUTO 거절 검사를 별도로 추가했습니다. 추가 HTTP 테스트의 응답 fixture도 매 요청 새 Response를 반환하도록 구성했습니다.

빌드에는 Zod 내부 PURE 주석 경고 2건과 ExcelJS 약 937KB(압축 전) 청크 크기 경고가 남습니다. 빌드 실패는 아니며 ExcelJS는 다운로드 때 지연 로드됩니다. PWA 사전 캐시는 37개 항목, 약 1.91MiB입니다.

## 개발 의도와 기반

소상공인이 익숙한 팀 채팅에서 영수증·텍스트 근무 내역을 올리고, 전체를 정리한 뒤 문제가 있는 부분만 확인해 구매가격·일정을 확정하도록 구성했습니다. 영수증 인식값은 사람의 승인 전까지 구매 이력과 메뉴 원가에 반영하지 않으며, 입고 수량 검수와 가격 승인을 별개로 관리합니다. 근무표는 원문에 없는 연도·직원 연결·휴게 시간을 임의 확정하지 않습니다.

처음 제공된 프로젝트 인수인계 Markdown과 사용자 피드백을 기준으로 React 19 + TypeScript + Vite로 구현했습니다. React Router로 화면을 나누고, TanStack Query로 비동기 상태를 관리하며, Zod·공통 도메인 함수로 값과 상태 전이를 검증합니다. Recharts는 가격 차트, ExcelJS는 근무표 출력, vite-plugin-pwa는 설치 메타데이터·앱 캐시·업데이트를 담당합니다. 데모는 IndexedDB를 사용하고 실제 서비스용 REST API 어댑터를 분리했습니다. 화면은 독립 CSS와 네이티브 dialog·폼으로 구성했습니다.

## 확인 한계

- 실제 OCR·인증·팀원 공유·사업장 권한 서버는 연결되어 있지 않습니다. 테스트 통과는 프론트와 로컬 데모·HTTP 계약 기준이며 운영 서버 통합이나 보안 검증 결과를 의미하지 않습니다.
- iPhone Safari/PWA의 실제 키보드·자동 확대·설치·카메라는 실기기로 검증하지 못했습니다. 모바일 뷰포트 검사와 실제 iOS 동작은 구분해야 합니다.
- 서버 중지 후 캐시 재접속은 확인했지만 장치의 네트워크 자체를 끈 검사는 아닙니다. 오프라인 쓰기 거절은 navigator.onLine을 대체한 자동 테스트로 확인했습니다.
- 메뉴 마진은 식재료 기준 예상값으로 인건비·임대료·수수료 등을 제외합니다. 서로 다른 포장 단위를 자동 환산하지 않습니다.
- 사용자가 제공한 실제 영수증·직원 자료를 외부 서비스로 전송하지 않았습니다. 브라우저 검증 데이터는 분리한 로컬 테스트 주소에 남습니다.
