## 화면과 데이터 흐름

- 사이드바 사업장 버튼으로 사업장을 선택·추가합니다. 로컬 데모는 사업장별 채팅·구매 기록·직원·근무표를 분리 저장합니다. 사업장 전환 시 대시보드로 이동하고 화면을 새로 고칩니다. API 모드는 `/workspaces` 및 `X-Workspace-Id` 연동 제안을 사용합니다.
- 팀 채팅의 + / 문서 올리기 → 영수증 또는 근무표 선택.
- 영수증 → 수기 / 인쇄형 / 전자문서·PDF 선택 → 파일 첨부. 초기 선택값 없음. 파일 첨부 단계 전에는 파일 입력을 노출하지 않습니다. 형식 변경 시 첨부 파일을 비웁니다.
- 근무표 → 파일 첨부 → 접수·분석 상태 → 쉬프트 초안.
- 근무표 목록 `/schedules`: 주간·전체 날짜 보기, 직원 필터, 이전·다음 주 이동, 확정된 일정의 `.xlsx` 다운로드를 제공합니다. 엑셀에 직원·일자·출퇴근·총근무·휴게·실근무·원본 문서 열과 고정 헤더·필터를 넣습니다. 휴게 시간이 비어 있으면 실근무 시간도 비워 둡니다.
- 상세 `/schedules/:scheduleId`: 원본 이미지 확대 또는 PDF 열기, 직원 연결, 시작·종료 일시, 휴게 시간, 행 추가·삭제, 행별 원본 확인 체크, 초안 저장, 쉬프트 확정.
- 확정 전 필수 입력·기간·중복 직원 일정·행별 원본 확인 여부를 확인합니다. 야간 근무는 종료 날짜를 다음 날로 입력합니다. 휴게 시간 미기재는 null이며 0분으로 추정하지 않습니다.
- 확정된 근무표만 일정에 반영합니다. 직원은 근무표 검토 화면에서 추가할 수 있습니다. 현재 확정 취소·확정 후 수정·급여 계산은 제공하지 않습니다. 실제 서버의 권한·직원 목록·일정 저장은 백엔드가 담당합니다.
- 저장하지 않은 변경은 표시하고 새로고침·창 닫기 시 브라우저 경고를 요청합니다. 앱 내부 메뉴 이동 전에는 사용자가 초안을 저장해야 합니다. 저장하지 않은 쉬프트가 있으면 PWA 업데이트를 막습니다.

## 데모

실제 이미지의 OCR을 흉내내지 않습니다. 실제 파일은 빈 쉬프트 초안으로 열리고 원본을 보며 직접 입력합니다. 가상 근무표 버튼은 2개 행과 가상 직원을 제공합니다. 2행은 이름과 휴게 시간이 불명확하여 사용자 확인이 필요합니다. 가상 날짜는 샘플 생성일입니다.

근무표는 IndexedDB `sikjangbu-schedules-v1`, 기존 영수증은 `sikjangbu-demo-v1` 키를 사용합니다. 이름 변경 시 기존 데이터를 유지하기 위해 저장 키를 바꾸지 않았습니다. 근무표도 브라우저·주소별 로컬 데이터이며 팀 공유 기능은 실제 서버 연결 후 가능합니다.

중복 파일은 보안 컨텍스트에서 SHA-256을 사용합니다. Web Crypto digest가 없는 로컬 HTTP 환경에서는 저장된 파일 내용(data URL)을 비교합니다. 로컬 ID 생성은 getRandomValues 기반 UUID를 지원합니다. 실제 서버는 독립적으로 중복 검사를 수행해야 합니다.

## 백엔드 연동 제안

실제 서버에서 확인된 명세가 아닙니다. `src/shared/api.ts`의 `httpScheduleApi`와 `src/shared/schedules.ts`를 기준으로 합의·조정해야 합니다. API 모드는 기존 `VITE_API_MODE=http` 설정을 공유합니다.

일반 요청은 선택 사업장을 `X-Workspace-Id` 헤더로 보냅니다. 목록·생성 외 모든 관련 API는 서버 측 사업장 권한 검사가 필요합니다. 사용자나 클라이언트 헤더를 신뢰해 접근을 허용하지 않습니다.

| 요청 | 입력 | 응답 |
|---|---|---|
| POST `/work-schedules` | multipart `file`, `room_id`, `document_type=WORK_SCHEDULE` | `{schedule_id}`; 202 권장 |
| GET `/work-schedules` | 없음 | `WorkSchedule[]` |
| GET `/work-schedules/{id}` | 없음 | `WorkSchedule` |
| PATCH `/work-schedules/{id}` | `{version, shifts: ShiftDraft[]}` | 204 또는 JSON; 이후 GET |
| POST `/work-schedules/{id}/confirm` | `{version, idempotency_key}` | 204 또는 JSON; 이후 GET의 CONFIRMED 확인 |
| POST `/work-schedules/{id}/retry` | 없음 | 204 또는 JSON |
| GET `/employees` | 없음 | `[{id,name}]` |
| GET `/shifts` | 없음 | `ConfirmedShift[]`; 확정된 행만 반환 |

`WorkSchedule`: `schedule_id`, `room_id`, `version`, `status`, `created_at`(ISO instant), `file_name`, `file_type`, `image_url`(서명 URL/null), `shifts`, 선택적 `error`.

상태: `UPLOADED → PROCESSING → NEEDS_REVIEW → CONFIRMED`, 분석 실패는 `FAILED`. FAILED에서만 재시도합니다. 문서 조회는 처리 중 2초, 목록은 4초 간격입니다.

```json
{
  "id": "shift-1",
  "employee_id": "employee-1",
  "raw_employee_name": "김민수",
  "starts_at": "2026-10-27T22:00",
  "ends_at": "2026-10-28T06:00",
  "break_minutes": 60,
  "warnings": [],
  "reviewed": false
}
```

위는 가상 예시입니다. `ShiftDraft`의 일시는 **Asia/Seoul 벽시계 시각 `YYYY-MM-DDTHH:mm`**입니다. UTC 또는 오프셋 포함 시각을 반환하는 서버는 어댑터에서 변환해야 합니다. 확정된 행인 `ConfirmedShift`에는 `schedule_id`가 추가됩니다.

채팅 API의 Message에는 영수증 `receipt_id` 또는 근무표 `schedule_id` 중 하나를 포함합니다. 서버가 업로드와 메시지 생성을 함께 처리해야 합니다. 데모에서는 근무표 저장소를 채팅 목록에 합쳐 제공합니다.

초안 저장은 미완성 행을 허용합니다. 확정 시 서버가 직원 소속·권한, 기간, 휴게 시간, 기존 확정 일정과 겹침, 모든 행 확인 여부를 다시 판단해야 합니다. 클라이언트가 보낸 경고나 reviewed 값만으로 검증을 생략하지 않습니다. 버전 충돌은 409로 응답하며 승인과 쉬프트 생성은 트랜잭션·멱등 처리가 필요합니다. 재시도에서도 같은 버전은 같은 확정 키를 사용합니다.

실제 분석 파이프라인(파일 저장, OCR, 직원 매칭, 쉬프트 초안 생성)과 직원 데이터베이스는 백엔드 구현 범위이며 이 저장소에는 포함되지 않습니다.

## PWA와 실행

- 표시 이름·HTML 제목·Apple 홈 화면 이름·manifest를 ZC FNB로 변경. manifest ID는 기존 시작 주소 `/dashboard`를 유지하여 같은 앱 정체성을 유지합니다.
- 홈 화면 바로가기에 팀 채팅과 근무표 추가. 앱 셸 사전 캐시와 수동 업데이트 방식 유지.
- 설치됨/설치 버튼/수동 설치 방법/HTTP 설치 불가를 구분. 설치 실패·서비스 워커 등록 실패 안내 추가.
- 서비스 워커 준비 상태를 설정 화면에 표시. API나 업로드한 원본은 서비스 워커 캐시에 저장하지 않습니다. 로컬 데모 원본은 IndexedDB 저장입니다.
- `개발서버.ps1 -Lan`: 같은 네트워크의 휴대폰에서 PC IP로 화면 확인. HTTPS 인증서를 만들어 주지는 않습니다.
- `개발서버.ps1 -Build -Preview -Port 4173`: npm 없이 Vite로 최신 소스를 빌드하고 미리보기. 기본 포트는 5173이며 다른 서버가 사용 중이면 종료하거나 다른 포트를 선택합니다.
- PWA 설치는 빌드 결과를 HTTPS로 배포하거나 PC localhost에서 진행합니다. 기존 설치 앱의 이름 갱신 시점은 브라우저가 결정하며 필요시 제거 후 다시 설치합니다.
