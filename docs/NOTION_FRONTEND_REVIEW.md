## 원문 확인과 적용 범위

[웹 개발 기획서 템플릿 | 팀 프로젝트](https://app.notion.com/p/406ef69dcaff812ba0cbd9567ab2476a)의 7개 하위 문서와 화면·기능·테이블·필드·API·정책 DB 6개를 읽었습니다. 전체 39개 행은 모두 ‘작성 양식’ 또는 ‘예시’이며, ‘실제’ 항목은 0개였습니다. 조회 결과는 모두 has_more=false였습니다.

따라서 `/items` CRUD, 공개 접근, 소유자 전용 수정, DB 종류, 인증 방식 등을 ZC FNB의 확정 요구로 취급하지 않았습니다. 사용자가 이미 정한 영수증 형식 선택, 채팅 중심 입력, 텍스트 근무표, 사람의 검토·확정, 사업장 분리 및 PWA 방향을 유지했습니다. 실제 서비스 정책이 아직 정해지지 않은 부분은 별도로 남겼습니다. Notion 원문과 DB는 수정하지 않았습니다.

## API·데이터 협의가 필요한 부분

- 현재 REST 어댑터의 인증·사업장 권한·수정 필드 계약은 프론트의 협의안입니다. Notion 예시 API가 실제 서버 계약을 확정한 것은 아닙니다.
- 입고 PATCH는 `{version, received_on, checked_by, completed, lines:[{item_id, actual_quantity, wrong_item, note}]}`를 전송합니다. 서버는 거래처·명세 품목·원본 수량·단위·승인 상태·결과 상태·확정 시각을 직접 조회·계산해야 합니다. 버전은 서버 원본 변화와 함께 검증해야 합니다. 원본 변경 시 검수 버전을 무효화할지, 별도 원본 버전 조건을 받을지는 서버와 합의해야 합니다. 로컬 데모의 기존 원본 비교 검사는 유지했습니다.
- 오류 협의안은 `{error:{code,message,fields?:{필드명:문자열 또는 문자열배열}},request_id?}` 및 `X-Request-Id`입니다. 코드·헤더가 없어도 기존 오류 문구로 동작합니다.
- 역할별 조회·수정·승인 권한, 개인정보 보존·삭제·복구, CSRF/CORS·쿠키, 변경 요청의 멱등 키 범위와 보존 기간은 팀·서버의 결정 사항입니다. 프론트 버튼 숨김만으로 권한을 보장하지 않습니다.
- 같은 계정 재인증은 현재 탭의 입력만 유지합니다. 새로고침·탭 종료 후 초안 복구나 다른 계정으로의 입력 이전은 제공하지 않습니다. 비밀번호·업로드 파일·편집 내용을 재인증 용도로 영구 저장하지 않습니다.

## 검증

- 전체 자동 테스트: 8개 파일 **111개 통과**. 기존 76개에 정책·요청 테스트 27개, React UI 테스트 8개를 추가했습니다.
- TypeScript 검사, 프로덕션 빌드, PWA 구성 검사 모두 통과했습니다. 최신 `dist/`와 서비스 워커를 생성했습니다. PWA 캐시는 37개 항목·약 1.96MiB입니다. ExcelJS 청크 크기 및 Zod PURE 주석 경고는 기존과 동일하게 남습니다.
- React UI 테스트는 jsdom에서 실제 컴포넌트를 렌더링하고 API를 대체합니다. 로그인 복귀, 세션 만료 중 폼 유지, 필드 오류, 없는 상세 복귀, 뒤로 가기·링크·새로고침 보호, 저장 중 이동 차단, 모달 취소·제목 ID를 검사합니다.
- jsdom을 개발 의존성에 추가했습니다. UI 테스트 실행에는 Node 22.22.2 또는 24.15 이상을 사용하며, 검증 PC는 Node 24.22.1입니다. 운영 번들에 jsdom은 포함하지 않습니다.
- 내장 브라우저는 webview 연결 시간 초과·디버거 연결 해제로 이번 화면 시각 검증을 완료하지 못했습니다. 이전 QA의 모바일 캡처를 이번 변경의 검증 증거로 사용하지 않습니다. 실기기 iOS 및 실제 운영 서버 연동도 별도 검증이 필요합니다.
- 임시 확인용 서버는 종료했습니다. `scripts/qa-policy-server.mjs`는 합성 계정·문서만 제공하는 수동 UI 검증 도구이며 운영 서버가 아닙니다. 실행 시 127.0.0.1:5190만 사용합니다. 계정은 `qa@example.test`, 비밀번호는 `qa-only-password`이며 실제 사용자 정보와 무관합니다. 첫 품목 저장은 401, 재인증 후 두 번째는 422, 세 번째는 503, 네 번째는 성공 응답으로 복구 흐름을 재현합니다. 종료는 Ctrl+C입니다.
