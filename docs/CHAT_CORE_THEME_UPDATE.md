# 공통 테마 · 원가 홈 · 채팅 핵심 기능

2026-10-28. 사용자의 요청대로 소스를 수정했다. 이번 변경은 자동 테스트·타입 검사·빌드·실기기 검증을 실행하지 않았다. 기존 `dist/`는 이전 빌드이며 프로덕션 미리보기를 쓰는 경우 재빌드가 필요하다.

## 화면 적용

- `src/theme.css`에 브랜드·배경·텍스트·테두리·성공·경고·오류 역할을 모았다. 파랑이 기본이며 **앱 설정 및 설치 → 화면 색상**에서 청록·인디고를 선택한다. 선택은 브라우저에 저장한다.
- 채팅방 배치와 입력 구조를 유지하면서 배경·내 말풍선·전송 버튼을 선택한 브랜드 계열로 맞췄다. 성공/주의/오류 의미색은 테마와 별도로 유지한다.
- 보고서의 날짜 묶음을 분리하고 작은 화면에서는 시작일·종료일을 각각 한 줄로 배치한다. iOS 날짜 내부 텍스트의 줄바꿈·기본 너비·여백을 조정했다.
- 홈 날짜 필드는 일정한 높이와 너비를 사용한다. 바로가기의 숫자 배지는 타일 안쪽 상단, 추가 버튼은 안쪽 하단에 고정하며 기본 버튼 패딩을 제거해 중앙을 맞췄다.

## 원가 중심 홈

8개 업무 바로가기 아래에 **원가·구매 핵심 현황**을 추가했다.

- 선택 날짜 기준 당일/주간/월간 확정 구매 합계
- 레시피 기준 원가율과 예상 식재료 마진율
- 최근 7일 확정 구매 추이
- 원가 상승 순 주요 메뉴 5개의 판매가·원가·원가율·예상 마진·직전 단가 대비 변화
- 원가 보고서와 매입 업무 센터 연결

합산 원가율은 계산 가능한 메뉴 각각 1개씩의 식재료 원가 합계를 판매가 합계로 나눈 값이다. 설정 부족 메뉴는 제외 건수를 표시한다. 현재 판매량·재고 사용량·회계 장부가 없으므로 실제 매장 원가율·손익으로 표시하지 않는다. 기간 선택은 구매 지표에 적용하고 레시피 지표는 현재 레시피·최근 확정 단가를 따른다.

## 채팅 사용

- 메시지를 약 0.5초 누르거나 PC에서 오른쪽 클릭/메시지 메뉴를 선택한다. 손가락 이동·스크롤·포인터 취소 시 길게 누르기를 취소한다.
- **복사 / 답장 / 공유 / 대화 링크 / 전달 / 내가 보낸 메시지 삭제**를 제공한다.
- 복사·공유는 기기 기능을 사용한다. 지원하지 않는 환경에서는 복사로 전환하고, 복사도 불가능하면 선택 가능한 텍스트를 보여준다. 전달은 대상 채팅방을 고른 뒤 사용자가 전송을 눌러야 실행한다. 첨부 파일 자체나 원본 접근 권한은 전달하지 않는다.
- 답장은 원문 인용을 표시하며 인용을 누르면 원래 위치로 이동한다. 사진·PDF 첨부 답장도 지원한다.
- 삭제 시 메시지를 삭제 표시로 바꾸고 연결된 영수증·근무표 데이터는 유지한다. 조회 시 만들어지는 기존 근무표 카드는 삭제 대상으로 노출하지 않는다.
- 검색은 전체 대화를 그대로 유지하며 최신 일치 항목으로 이동한다. 이전/다음 결과 이동, 결과 위치 표시, 키워드 강조를 제공한다. 긴 근무 현황도 검색 중 원문을 펼친다. 검색을 닫은 뒤에도 해당 위치에서 앞뒤 기록을 볼 수 있다.
- 채팅방 메뉴에 참여자 목록·방장/관리자 표시·사업장 구성원 초대·내보내기 확인을 추가했다. 방장·본인은 내보내기 대상에서 제외한다.

## 서버 연동 계약 — 백엔드 합의 필요

현재 기본 모드는 브라우저 로컬 데모다. 참여자 추가·제거는 사업장별 IndexedDB에 저장되는 데모이며 실제 사람에게 초대를 보내지 않는다. 아래 HTTP 어댑터는 프론트에서 준비한 **제안 계약**이며 백엔드 구현 여부를 확인한 API가 아니다.

| 메서드 · 경로 | 요청/응답 |
|---|---|
| `GET /chat/users` | 현재 사업장에서 초대 가능한 사용자 `[{id,name,role}]` |
| `GET /chat/rooms/:room/members` | `{members:[{id,name,role}],can_invite:boolean,can_remove:boolean}` |
| `POST /chat/rooms/:room/members` | `{user_ids:string[]}` → 204 |
| `DELETE /chat/rooms/:room/members/:user` | 204 |
| `POST /rooms/:room/messages` | 기존 `{text}`에 선택 필드 `reply_to:원본메시지ID` 추가 |
| `POST /rooms/:room/messages/attachments` | 기존 파일 FormData에 선택 필드 `reply_to` 추가 |
| `DELETE /rooms/:room/messages/:message` | 메시지 삭제 표시 → 204 |

메시지 응답 확장:

```json
{
  "id": "message-id",
  "text": "답장 내용",
  "reply_to": { "id": "original-id", "author": "작성자", "text": "원문 요약" },
  "deleted_at": null
}
```

`deleted_at`은 삭제 시 ISO 시각 문자열이며 미삭제는 생략/null을 허용한다. 역할은 `OWNER | ADMIN | MEMBER`다. 모든 요청은 기존 쿠키 인증과 사업장 헤더를 따른다. 서버는 방 접근 권한, 사업장 소속, 초대·내보내기 권한, 마지막 방장 보호, 원문이 같은 방에 속하는지, 본인 메시지 삭제 조건을 검증해야 한다. 삭제된 원문은 인용 스냅샷에서도 삭제 표시로 바꾼다.

현재 대화 검색은 메시지 API가 반환한 기록을 대상으로 한다. 로컬 데모는 전체 기록을 반환한다. 서버가 페이지 방식으로 바뀌면 서버 검색과 해당 메시지 전후 기록 조회 계약도 함께 추가해야 한다. 실시간 소켓·푸시 알림·읽음 집계는 이번 변경 범위가 아니다.
