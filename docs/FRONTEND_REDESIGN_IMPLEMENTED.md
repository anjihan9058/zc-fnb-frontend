# 프론트 재설계 구현 기록

2026-10-28 · [설계서](ZC_FNB_PRODUCT_REDESIGN_PLAN.md)의 프론트 범위를 반영했다. 현재 실행 기본값은 브라우저 로컬 데모이며, 팀원 간 공유·실제 OCR/AI 분석·실시간 알림·은행·회계는 연결 완료 상태가 아니다.

## 변경 내용

- 영수증 업로드의 수기/인쇄/전자·PDF 선택, 형식 변경, 형식 필수 검사를 제거했다. 촬영·파일 선택·미리보기·전송으로 바로 진행한다. PDF 파일은 계속 첨부할 수 있다.
- HTTP 업로드는 `file`, `room_id`를 보낸다. `upload_mode`, `receipt_format`, `document_type`을 보내지 않는다. 이는 협의할 새 업로드 계약이며, 실제 서버가 옛 필드를 요구하면 백엔드 변경이 필요하다.
- 이전 문서의 `upload_mode`는 선택적 레거시 메타데이터로 읽는다. 기존 IndexedDB 기록을 삭제하지 않는다. 새 로컬 파일 업로드는 유형을 정하지 않고 실제 OCR 값도 만들어내지 않는다.
- 운영 홈을 처리할 일, 기간별 확정 구매, 오늘 근무, 최근 문서, 선택 가능한 구매단가 추이와 메뉴 원가 변동으로 바꿨다. 양파/단위 고정 차트를 제거했다. 미처리 업무는 기간 필터와 별개로 표시한다.
- 짙은 청색 업무 내비게이션과 구매·원가/팀 운영 메뉴 묶음, 표 중심 문서 목록, 일관된 상태 탭·상세 패널을 적용했다. 모바일 메뉴는 홈·채팅·근무표·원가·더보기다. 채팅방은 기존 전체 화면을 유지한다.
- 문서 목록에 상태·거래일 범위·검색을 추가했다. URL에 조건을 보관하고 상세에서 목록으로 돌아올 때 복원한다. PC는 표, 모바일은 문서 카드를 쓴다.
- 검토 화면은 PC 왼쪽 정보/품목, 오른쪽 고정 원본으로 재구성했다. 모바일은 분석 내용/원본을 전환한다. 전체/문서 정보/품목/활동 이력 탭과 전체/문제만/미연결 필터, 다음 문제 수정, 이전/다음 문서 이동을 제공한다. 원본 확대와 PDF 미리보기·다운로드도 제공한다.
- 실제 활동 이력이 응답에 있는 경우에만 표시한다. 빈 이력에 가짜 담당자·승인 시각을 만들지 않는다. 이전/다음 문서는 이미 불러온 목록 범위에서 이동한다.
- 긴 근무 현황 메시지에 대한 기존 정리 기능을 유지한다. 일반 대화를 AI로 분석하는 기능은 추가하지 않았다. 정리한 원문 메시지에는 연결된 근무표 카드를 붙이고, 확인·확정 상태를 조회한다.
- 근무표의 직원별 전체 요약·문제 행 수정·공통 휴게·익일·겹침 검사를 유지하고, 주간/전체 외에 일간 시간대 보기를 추가했다. 새 문서 입력에서 지난 근무 현황/예정 근무표를 선택적으로 구분한다. 엑셀에도 용도를 기록하고 직원별 합계를 용도별로 나눈다.
- 원가 계산의 g↔kg, mL↔L 환산을 추가했다. 포장 단위·무게와 부피 사이 변환은 하지 않는다. 메뉴 사용량의 단위를 선택할 수 있으며 계산 내역에서 기준 구매 단위·환산량·거래처·기준일·근거 영수증·재료별 원가 비중을 확인한다.
- 영수증·근무표 검토에서 출처 채팅으로 이동하고 해당 메시지 위치를 표시한다. 로컬 영수증에는 실제 생성한 메시지 ID를 연결하며 이전 로컬 기록도 가능한 경우 연결한다.

## 응답 어댑터와 실제 서버 협의

`src/shared/receiptWire.ts`는 기존 평면 영수증 응답과 설계서의 `schema_version: "1"` 형태를 공통 화면 모델로 바꾼다. 후자는 프론트의 제안 계약이며 실서버 명세라고 주장하지 않는다.

- 상태와 버전·품목 ID·금액 자료형을 검증한다. 미확인 숫자는 null을 유지한다.
- 문서 분류는 업로드 선택과 분리해 결과로 표시한다. 낯선 문서 유형은 미확인으로 표시한다.
- 문서 문제·행 문제와 `can_edit`/`can_approve`를 반영한다. 승인 차단 이슈는 승인 버튼을 막는다.
- 백엔드는 AI 출력 JSON을 검증·정규화하고 실제 권한·필수 검증·승인 트랜잭션을 처리해야 한다. 프론트 버튼 제한이 서버 검사를 대신하지 않는다.

새 서버 계약에 추가로 맞출 부분은 선택적 `record_kind: PLANNED | WORKED`, 메뉴 계산 결과의 선택적 `receipt_id`, `purchase_unit`, `purchase_unit_price`, `quantity_in_purchase_unit`, 영수증 `amounts`, `activity`, `issues`, `capabilities`, `source_message_id`다. 없는 선택 필드는 빈 상태·미확인·근거 링크 생략으로 처리한다.

근무표 분석은 기존 제공 양식의 규칙 파서와 명시적 연도·직원 연결 계약을 유지했다. AI 근무표 분석용 새 API가 없는 상태에서 임의 엔드포인트를 호출하지 않는다. 서버가 원문을 먼저 분석해 반환하는 계약을 정하면 그 단계의 입력 부담을 줄일 수 있다.

## 유지한 범위와 외부 의존

로그인 복귀·재인증 시 편집값 유지, 미저장/저장 중 이동 보호, 영수증 승인 멱등성·버전 검사, 사업장 분리, 입고와 가격 승인 분리, PWA 수동 업데이트를 유지했다. 실제 서버 미연결 부분을 완료 기능으로 바꾸지 않았다. API 모드·주소 설정도 임의로 변경하지 않았다.

현재 메시지는 4초 폴링이며 과거 대화 커서·읽음·실시간 전달·푸시·직원별 승인 권한·파일 URL 권한은 서버 협의가 필요하다. 은행·회계·POS/재고 기반 실제 원가 화면은 구현하지 않았다.

## 확인 범위

자동 테스트 12개 파일·121개 통과(React 화면 테스트 10개 포함), TypeScript 타입 검사 통과. 유형 선택 없는 PDF 전송·목록 필터 복귀·AI 응답 변환·명확한 단위 환산·용도별 일정 겹침 검사를 포함한다. Vite 프로덕션 빌드와 PWA 정적 검사도 통과했고 최신 `dist/`를 생성했다. 서비스 워커 사전 캐시는 38개·약 2.00MiB다. 기존 Zod 주석 경고와 지연 로딩 ExcelJS 청크 크기 경고는 빌드를 실패시키지 않는다.

브라우저 자동화가 로컬 미리보기 탭을 연결하는 과정에서 시간 초과되어 실제 브라우저 시각 검증은 완료하지 못했다. 과거 화면 캡처를 이번 변경의 검증 자료로 사용하지 않았다. iPhone PWA의 키보드·PDF 미리보기·레이아웃은 실기기 확인이 필요하다.

## 직접 확인할 경로

1. 운영 홈 → 영수증 올리기: 형식 선택 없이 첨부/촬영으로 진입한다.
2. 로컬 데모의 가상 샘플 → 문서·구매 → 전체/문제만 필터 → 원본 대조 → 수정·승인.
3. 긴 근무 현황을 팀채팅에 전송 → 근무표로 정리 → 연도·직원 확인 → 전체 표/문제 수정 → 확정·엑셀.
4. 근무표의 일간 보기 → 익일 퇴근이 전날·다음날에 걸쳐 보이는지 확인.
5. 메뉴 레시피에 양파 150g 입력 → kg 구매 기록으로 환산한 원가와 근거 영수증 확인.

운영 데이터나 실제 OCR을 확인하는 절차가 아니라 현재 프론트·데모 동작을 확인하는 순서다.
