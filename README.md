## 실행

Node.js 24.15 이상 권장(검증 환경 24.22.1), pnpm 또는 npm을 사용합니다. Node 22에서는 전체 UI 테스트의 jsdom 의존성 때문에 22.22.2 이상이 필요합니다. 최초 설치에는 npm 레지스트리 네트워크 접근이 필요합니다.

```bash
pnpm install
pnpm dev
```

기본 주소: `http://localhost:5173`. 별도 환경변수 없이 데모로 시작합니다.

```bash
pnpm test        # 도메인 및 저장·승인 통합 테스트
pnpm typecheck   # TypeScript 검사
pnpm build       # dist/ 생성 + 서비스 워커
pnpm preview     # http://localhost:4173, PWA 빌드 확인
```

npm 사용 시 `npm install`, `npm run dev`, `npm test`, `npm run build`도 가능합니다. 팀에서는 `pnpm-lock.yaml` 기준 사용을 권장합니다.

이 PC는 기본 PATH에 npm이 없지만 Codex 제공 Node·pnpm으로 설치되어 있습니다. `개발서버.ps1`은 설치된 프로젝트를 실행하고, Node가 PATH에 없을 때 Codex 런타임을 확인합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\개발서버.ps1
```

휴대폰과 같은 네트워크에서 화면 확인: `-Lan` 옵션을 추가하고 휴대폰에서 `http://PC의IPv4주소:5173`으로 접속합니다. Windows 방화벽과 핫스팟의 기기 간 접속 정책이 연결을 허용해야 합니다.

최신 소스를 빌드하고 PWA 미리보기로 실행하려면 아래 명령을 사용합니다. npm이 PATH에 없어도 동작하도록 제공 Node 경로를 사용합니다. 이 스크립트의 `-Build`는 Vite 빌드이며 테스트·타입 검사를 함께 실행하지 않습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\개발서버.ps1 -Build -Preview -Port 4173
```

빌드 결과는 `dist/`에 생성됩니다. 휴대폰 PWA 설치에는 해당 결과를 HTTPS로 제공하는 호스팅이 필요합니다. LAN의 HTTP 미리보기 주소에서는 설치할 수 없습니다. 이전 서버는 해당 PowerShell 창에서 `Ctrl+C`로 종료합니다.

명령의 실행 정책 옵션은 이 실행 프로세스에만 적용됩니다. 전역 설정을 바꾸지 않습니다. 수동 실행은 `node node_modules/vite/bin/vite.js`입니다.

## 시연 순서

1. **우리 팀 채팅** → 입력창 옆 **+** → **영수증** → **가격 급변** 가상 샘플.
2. 업로드 완료 → AI 분석 중 → 확인 필요 상태를 확인합니다.
3. 영수증 확인 → 원본에는 양파 단가 2,500원, 추출값은 25,000원인 예시입니다.
4. 양파 수정 → 단가 `2500`, 금액 `7500` → **저장 및 재검증**.
5. **검토 완료 및 승인** → **구매가격 확정**.
6. **식재료 가격**에서 승인된 기록이 새로 생겼는지 확인합니다.

정상·가격 급변·단가 누락·금액 불일치·규격 미확인·분석 실패 6개 샘플이 있습니다. 실제 사진을 업로드하면 브라우저에 원본을 저장하고 **빈 항목을 직접 입력**하도록 안내합니다. 사진을 실제로 OCR한 것처럼 가상 값을 생성하지 않습니다. 현재 직접 입력은 1개 행 체험용이고, 임의 행 추가·삭제는 서버 계약 확정 이후 확장할 영역입니다.

## 구현 범위

- React 19 + TypeScript + Vite, React Router, TanStack Query, Zod, Recharts, Lucide.
- 모바일 하단 내비게이션 / 데스크톱 사이드바, 대시보드·팀 채팅·보관함·검토·가격·식재료 관리.
- 영수증은 형식 선택 없이 카메라/파일 첨부. 문서 유형은 분석 결과에서 확인. JPG/PNG/WebP/PDF 및 10MB 제한. 신규 근무표는 텍스트 입력으로 정리합니다. 기존 AUTO 문서는 조회만 유지합니다.
- 처리 상태 폴링, 실패 재시도, 업로드 중 중복 클릭 차단, 데모 파일 SHA-256 중복 검사.
- 원본 이미지 확대, PDF 다운로드, 문서 분류와 거래 정보 수정, 품목 매칭·수량·단가·금액 수정.
- 경고 우선 노출, 누락 가격 null 유지, 미승인 데이터 제외, 가격 급변 직접 확인.
- 승인 후 서버 상태 재확인, 캐시 갱신. 데모는 IndexedDB와 Web Locks를 이용해 반복/동시 승인을 직렬화합니다.
- 가격 차트, 식재료·업체·기간 필터, 전날/직전 비교 분리, 품목·별칭 등록/수정.
- PWA manifest, 192/512 아이콘과 maskable 아이콘, 앱 셸 캐시, 업데이트 확인, 설치 안내, 오프라인 안내.

Tailwind/shadcn은 필수 요구가 아닌 권장 옵션이므로 이 MVP에서는 독립 CSS 디자인 시스템과 접근성 있는 네이티브 dialog/폼을 사용합니다. 복잡한 폼 라이브러리 대신 Zod와 React 상태로 편집을 구성했습니다.


## 저장과 네트워크

데모 데이터는 해당 브라우저·주소의 IndexedDB(`keyval-store`, 키 `sikjangbu-demo-v1`)에 저장됩니다. 다른 기기·브라우저·포트와 공유되지 않으며 로컬 저장소 삭제 시 사라집니다. 실제 서비스 인증/DB를 대체하지 않습니다. 업로드 이미지는 데모 저장소에 포함됩니다.

웹 폰트는 Google Fonts의 Noto Sans KR을 사용하며 연결되지 않으면 시스템 한글 폰트로 대체됩니다. API 데이터와 실제 영수증 원본은 서비스 워커에 캐시하지 않습니다. 오프라인에서는 앱 셸을 열 수 있으나 업로드·수정·승인을 처리하거나 자동 재전송하지 않습니다.

## 실제 API 연결

[API_INTEGRATION.md](docs/API_INTEGRATION.md)를 참고해 `.env.local`에서 `VITE_API_MODE=http`와 `VITE_API_BASE_URL`을 지정합니다. 실제 서버와 협의할 확장 엔드포인트·응답 필드가 있으므로 환경변수만으로 임의 서버와 즉시 호환된다는 의미는 아닙니다.

남은 외부 작업: 실제 OCR/문서 추출, 인증·사업장 권한·팀원 공유 서버 연결, 서버 계산·검증·승인 트랜잭션, HTTPS 운영 배포. 레시피·판매가격·확정 단가가 빠진 메뉴의 원가율·마진율은 추정하지 않습니다. 행별 부분 승인, POS/재고/폐기율 및 카카오톡 직접 연동은 포함하지 않습니다.

## PWA 배포

`dist/`를 HTTPS 정적 호스팅에 배포하고, `/rooms/*`, `/receipts/*` 등 SPA 경로를 `index.html`로 fallback 처리합니다. `/api/*`는 API로 전달하고 HTML로 바꾸지 않습니다. `sw.js`에는 장기 캐시를 설정하지 않는 것이 좋습니다. `manifest.webmanifest` MIME과 아이콘 경로도 확인하세요.

로컬 PWA는 `pnpm build && pnpm preview`로 확인합니다. 개발 모드에서는 서비스 워커를 등록하지 않습니다. LAN의 HTTP 주소는 모바일 카메라/설치/보안 컨텍스트 제한이 있을 수 있어, 실제 iOS·Android 테스트는 HTTPS 환경에서 해야 합니다. iOS Safari 공유 → 홈 화면에 추가, 지원 Chromium의 설치 메뉴를 사용합니다. 업데이트는 저장 중인 내용을 보호하기 위해 자동 새로고침하지 않고 사용자에게 알립니다.
